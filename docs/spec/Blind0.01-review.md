# Blind0.01 规格评审（BlindSpire）

> 评审对象：`Blind0.01.txt`（初代功能描述，原文已复制为 `Blind0.01.txt`）
> 评审日期：2026-09-18；评审依据：STS2 v0.111.0 反编译源码（`.refs/sts2-v0.111.0/src`）
> 结论：**概念成立（盲玩信息隐藏 mod），但有 1 处内部矛盾、若干关键规则未定义，直接开工会有大量返工。**

## A. 阻塞级问题（需先拍板）

1. **战斗中"悬停显示牌面"与"牌面不可见"自相矛盾（最关键）**
   - 功能 1：所有牌面不可见，靠效果/音效猜牌，再手动匹配。
   - 功能 4.2：光标移到/选出手牌时"该牌卡面才可见"。
   - 若显示**真牌面** → 功能 1 在战斗中完全失效（逐张悬停即可识别全部手牌）。
   - 若显示**已匹配牌面** → 需定义未匹配时显示什么（空白/黑雾/统一卡背），且"悬停"只是放大当前匹配结果。
   - 建议：后者（显示"你给它贴的牌面"），并在规格里写明。
2. **"牌面"边界未定义，名称会泄漏身份**
   - 你的定义=插画+效果描述栏；但卡名、费用、类型图标、稀有度边框、升级标记不在内。
   - 名称保留 → 盲玩失效（名字即答案）；名称隐藏 → 需排查全游戏其他暴露卡名的地方（事件文本、奖励提示、商店、战斗日志、图鉴）。
   - 费用：4.2"费用区可见"指能量球还是卡上费用数字？若卡上费用可见、而匹配的牌面带自己的费用数字，错配时会出现"两个费用打架"。
   - 需要一张**隐藏/保留元素矩阵**（卡牌/遗物/药水/敌人/顶栏/各屏幕逐项列）。
3. **快照机制与战斗可玩性的冲突**
   - 战斗中血量显示旧快照 → 玩家不知道自己快死了（可能是设计意图，但要明说）。
   - 金币：商店购买/事件扣钱后是否刷新？不刷新则无法判断购买力。
   - 刷新触发器只写了"休息"，需列全（战斗结算？事件？商店？换层？Boss 遗物？）。
   - 显示形式：旧值保留 vs 显示"?"；最大生命提升/降低怎么处理。
4. **敌人的关键信息未定义**
   - 4.1 只处理了模型（呼吸源+受击保留）。但**意图**（攻击数值/类型，`NIntent`）、敌人 buff/debuff、意图攻防类型显示不显示？全隐藏会大幅改变难度，需要明确。
   - 受击效果"保留"是否含伤害数字？伤害数字会暴露敌人血量/增伤 buff。
5. **锻造揭示与其他升级来源的一致性**
   - 3.2 锻造后自动匹配正确牌面=升级即揭示身份（合理）。但事件升级、遗物升级（如铁匠类）是否同样揭示？
   - 升级预览（游戏有 `NUpgradePreviewTickbox`）怎么处理？
   - 匹配列表里"打击"与"打击+"是同一匹配还是两个条目？升级后是否要重新匹配？
6. **匹配系统的粒度与持久化未定（玩法核心）**
   - 按**卡牌定义**（5 张打击共享一个匹配）还是按**卡牌实例**（每张单独）？猜出一张打击是否所有打击都揭示？
   - 记忆保存范围：单局（存进存档，新局重置）还是跨局（全局知识库）？读档是否恢复？建议至少单局持久化。
   - 错配能否改（已写"可更改"）、是否有正确性反馈（如打出后提示匹配错误）？建议默认无反馈。
7. **"检视界面"不存在**
   - 游戏没有卡牌检视屏幕（只有遗物检视 `NInspectRelicScreen`）；卡牌放大是预览容器 `NCardPreviewContainer`（悬停/长按）。
   - 需要新建匹配 UI（可复用游戏图鉴 `NCardLibrary` 的检索/过滤器）。
   - 待定：入口手势（右键/长按/按钮）、列表范围（全卡池含未解锁 vs 仅拥有/见过）、是否区分角色/稀有度/升级版、匹配后是否全局生效（牌组视图/商店/事件都显示匹配牌面）。

## B. 范围与一致性

8. **"大部分游戏画面盖上黑雾"没有逐屏清单**：主菜单/角色选择/捏奥/地图/战斗/奖励/商店/事件/火堆/宝箱/牌组/图鉴/设置/结算——每屏的雾是"装饰暗角"还是"内容遮挡"？遮挡则奖励/商店/事件无法操作。
9. **黑雾 ≠ 信息隐藏**：若只是视觉滤镜，文字/图标仍可读；建议明确两层（视觉雾感 vs 内容级隐藏）并分别定义。
10. **奖励/商店/事件的盲选规则**：卡牌奖励看不到牌面时按什么选（边框色/稀有度/费用）？商店里名称与价格显示吗？事件文本提到卡名/遗物名怎么办？
11. **药水**：战斗外顶栏药水显示什么？名称/效果 tooltip？使用选目标时？商店购买时？（4.3 只定义了战斗栏位轮廓）
12. **遗物**：被动效果通过 buff 图标/计数器体现（如额外能量），战斗中的触发提示/浮字隐藏吗？Boss 遗物三选一（名字+效果）呢？
13. **地图**：当前节点/已走路径/Boss 图标/图例/画线工具（游戏有 `NMapDrawings`）显示吗？"下一层"=当前节点直接后继，需写清。
14. **战斗场景细节**：可见半径多大/是否随呼吸变化；多敌人/召唤物/死亡动画；玩家自己的 buff/能量/牌堆计数是否可见；敌人呼吸源如何绑定（敌人是 Spine 2D 骨骼动画，`NCreature.Body` 是 `Node2D`，技术上可做但不同敌人动画名不同，需要统一方案）。
15. **动态生成的牌**（战斗中"添加一张 X"、药水生成牌）默认规则应与"所有牌默认不可见、匹配按定义继承"一致，写进规格。

## C. 技术/实现风险

16. **补丁面很广**：本质是"全局 UI 可见性框架"，涉及 `NCard`（`_titleLabel/_descriptionLabel/_portrait/_frame`，NCard.cs:508-518）、`NTopBar`（Hp/Gold）、`NRelic`/`NRelicInventory`、`NPotion`、`NMapScreen` 各节点、`NCardRewardSelectionScreen`、`NCardLibrary`、`NIntent`、`NMapDrawings` 等。游戏升级（0.111.0→0.112+）大概率大面积失效——建议建立补丁目标清单 + 版本适配层，并明确只支持固定版本。
17. **依赖选型**：本项目不新增内容，用不到 BaseLib 的内容注册基类；真正需要的是 RitsuLib（生命周期、ModPatcher、RunSavedDataStore/ModDataStore 持久化、设置 UI、I18N）。建议评估 BaseLib 是否必需（少一个依赖少一份兼容风险）。
18. **多人模式**：游戏有联机（`RunManager.cs:516` 有 `IsMultiplayer` 分支）。可见性/匹配在多人的行为（各客户端各自盲玩？匹配同步？）必须定义，否则建议检测到多人时禁用或仅本地视觉。
19. **存档兼容与卸载安全**：匹配数据入存档后，卸载 mod 应可被安全忽略（RitsuLib 数据按 mod id 命名空间化，天然满足）；中途给已有存档启用 mod 的行为（旧牌是否全部变不可见）要定义。

## E. 现成可复用（利好）

- 图鉴 `NCardLibrary` + 检索/稀有度/费用/类型过滤器 → 匹配列表可直接参考。
- 卡牌预览容器 `NCardPreviewContainer` → 匹配 UI 的挂载点候选。
- 敌人为 Spine 2D 骨骼动画（`NCreature : Control`，Body 为 `Node2D`）→ 呼吸源可绑定骨骼动画相位。
- RitsuLib 的持久化/补丁/设置/本地化模块与本需求高度匹配。
